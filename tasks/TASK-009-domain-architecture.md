# TASK-009: Доменный и репозиторный слой

**Приоритет:** P1
**Статус:** не начато
**Зависимости:** `TASK-001`, `TASK-002`

## Проблема

`src/App.tsx` координирует состояние, persistence, нормализацию и доменные операции. Медиа дублируется в нескольких представлениях, а native save полностью очищает и пересоздаёт таблицы (`src-tauri/src/database.rs:293`). Это повышает риск рассинхронизации и ограничивает масштабирование.

## Объём работ

- Зафиксировать каноническую модель: персоны, отношения, медиа, привязки и теги лиц как отдельные сущности.
- Оставить у персоны только ссылки на медиа, включая `avatarMediaId`.
- Ввести application service с атомарными командами изменения дерева.
- Разделить `BrowserTreeRepository` и `TauriTreeRepository` за общим контрактом.
- Ввести версию схемы и последовательные миграции.
- После стабилизации модели перейти от full-table rewrite к изменениям сущностей и ревизиям.
- Не совмещать структурный рефакторинг с визуальными изменениями.

## Проверки

- Contract tests выполняются для обоих репозиториев.
- Команды удаления, привязки и импорта имеют одинаковый результат во всех режимах.
- Миграция существующей базы не теряет данные.
- Сбой в середине команды не оставляет частичное состояние.

## Готовность

- [ ] У модели есть единственный источник истины для каждой сущности.
- [ ] React-компоненты не реализуют правила целостности данных.
- [ ] Оба репозитория соответствуют одному контракту.
- [ ] Схема версионируется и мигрируется транзакционно.
- [ ] Частичные обновления не требуют полной перезаписи таблиц.
- [ ] Регрессии `TASK-001` и `TASK-002` остаются зелёными.
