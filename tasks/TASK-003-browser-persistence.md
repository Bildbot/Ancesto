# TASK-003: Надёжное браузерное сохранение и импорт

**Приоритет:** P0
**Статус:** не начато

## Проблема

IndexedDB-сохранение завершается на `putRequest.onsuccess` в `src/services/db.ts:351`, хотя транзакция ещё может быть отменена. Загруженные из IndexedDB и `localStorage` данные проходят только поверхностную проверку. Импорт сообщает об успехе до подтверждённого commit, а fallback `localStorage` оставляет тяжёлый `mediaArchive` и обычно повторно превышает квоту.

## Объём работ

- Завершать Promise только на `transaction.oncomplete`.
- Отклонять Promise на `transaction.onerror` и `transaction.onabort`.
- Закрывать соединение после фактического завершения транзакции.
- Применять полную версионированную валидацию ко всем read-path.
- Сделать callback импорта асинхронным и показывать успех после commit.
- Хранить в `localStorage` только явно определённый облегчённый fallback без binary payload.
- При повреждении данных не перезаписывать исходное состояние автоматически.

## Проверки

- Тест последовательности `put.onsuccess` -> `transaction.onabort`.
- Тест повреждённых данных в IndexedDB и `localStorage`.
- Тест quota error с большим `mediaArchive`.
- Компонентный тест сообщения об успешном и неуспешном импорте.

## Готовность

- [ ] Сохранение подтверждается только после commit.
- [ ] Abort и ошибки транзакции доходят до UI.
- [ ] Все загружаемые данные глубоко валидируются и мигрируются.
- [ ] Импорт не показывает ложный успех.
- [ ] Fallback не пытается записать binary payload в `localStorage`.
- [ ] Добавлены и проходят регрессионные тесты.
