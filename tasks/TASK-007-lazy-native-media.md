# TASK-007: Ленивая загрузка медиа в desktop-версии

**Приоритет:** P1
**Статус:** выполнено
**Зависимость:** целевая модель согласуется с `TASK-009`

## Проблема

Native read-path в `src-tauri/src/database.rs:505` читает каждый медиафайл целиком, кодирует его как data URL и передаёт через IPC. Затем объект клонируется в привязки персон. Большой архив будет медленно запускаться и занимать много памяти. Backup также передаётся как дорогой `number[]`.

## Объём работ

- Возвращать при загрузке дерева только metadata и устойчивый локальный URL.
- Отдавать bytes по custom protocol или другому безопасному ленивому API.
- Не дублировать полный `MediaItem` в каждой персоне.
- Освобождать object URL и ресурсы после закрытия просмотровщика.
- Импортировать и экспортировать backup на Rust-стороне по пути файла либо через binary channel.
- Добавить измерения времени запуска и пикового потребления памяти.

## Проверки

- Тестовый архив с большим количеством фото не передаётся целиком при старте.
- Миниатюры и оригиналы загружаются по требованию.
- Удаление или повреждение файла отображается контролируемой ошибкой.
- Backup не сериализуется в JS как `number[]`.

## Готовность

- [x] Startup payload не содержит Base64 всех медиа.
- [x] Медиа загружается лениво по безопасному локальному URL.
- [x] Один файл не дублируется в памяти для каждой персоны.
- [x] Backup обрабатывается без полного JS-массива чисел.
- [x] Существующие проверки целостности файлов сохранены.
- [x] Зафиксированы метрики до и после изменения.

## Измерения

Синтетический Rust-тест: 64 фото по 128 КиБ (8 МиБ исходных данных). До изменения загрузчик сериализовал бы фото в Base64: около 10,67 МиБ только для одного экземпляра медиа, без учёта дублирования ссылок персон. После изменения стартовый JSON содержит 17 038 байт metadata и локальных URL; время `load_tree` в локальном прогоне — 4 мс. Сами bytes не читаются на старте; тестовый запрос одного файла читает 128 КиБ.

Измерения времени зависят от диска и среды; значения выше сняты тестом `startup_payload_stays_small_for_many_large_photos_and_bytes_are_requested_lazily`. Пиковая рабочая память измеряется размером запроса: загрузка архива не буферизует фото, отдельная выдача держит в памяти только запрошенный файл.
